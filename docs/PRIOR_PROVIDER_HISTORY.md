# Record payroll paid by a prior provider

This workflow is for an existing live client whose legal employer/EIN is unchanged and whose earlier payroll was already paid. It preserves the employee roster and records one complete employer/year history. It does not issue checks, pay employees, post liabilities, create deposits, repay loans, send email, or enqueue tax/source sync.

The clean-client QuickBooks import remains available in Data Migration. An existing roster uses **Settings → Client Management → Prior-provider history**. Any staff user who can run and commit this client's payroll (super admin, org admin, admin, manager, or an accountant with access to the client) can do every step: review, save progress, record, turn on year-to-date and undo. This reuses the existing `payroll_operations` capability plus client access, rechecked inside each operation. Client and employee users have no access.

6. Assign a named operator. Mark or Benjo (accountants assigned to the client) can complete the whole workflow. Recording history turns on Historical payroll for the client automatically; no separate client-settings change is needed.

## Operator procedure

1. Open the intended client’s **Prior-provider history** page from Client Management. Confirm the company badge. The page shows five steps (Pay dates, Employees, Match registers, Record, Turn on YTD) and a **What’s left** list. Progress saves automatically and is shared with other staff on this client, so anyone can resume at any step; if someone saved newer changes, the page asks you to load their version instead of overwriting it. Enter the provider name; the takeover date is prefilled as the first of the month after the last listed pay date (November 1, 2026 for Kasperbauer).
2. Select the 20 existing calculated regular runs dated January 14–October 28. Their 60 paycheck rows prefill the review. Published/connected-source, parallel, corrective, already committed, numbered, printed or otherwise financially used runs are rejected. Every other native run must be resolved before initial conversion.
   Runs calculated before the staging-v2 upgrade are selected and converted exactly as saved. Do not recalculate them: their period lengths and pay dates (for Kasperbauer, 14- and 21-day periods paid on the period end for a semimonthly roster) are source evidence, not schedule errors. The upgraded approval path asks old calculations to be recalculated; history conversion never approves them and does not need that. If an older calculation cannot attribute an employer contribution, that amount prefills blank and must be entered from the paid register.
3. Continue to reconciliation. Match the provider’s employee names and SSN last four to the existing roster. No employee is created, deleted, terminated or relinked to another client.
4. In **Match registers**, open each pay date next to the provider’s register. Every paycheck is prefilled from the saved run; correct anything different. Enter where it is on the register (a register name can fill every blank reference). Problems appear next to the field with the exact difference (for example, a net that doesn’t equal gross less taxes and deductions). Select **Matches the register** when the totals agree, or **Totals are different** to type the register totals and see each column’s difference. A mismatch blocks recording, and each pay date must be matched individually; there is no bulk “trust every calculation” action.
5. Open **Taxable wages, employer taxes and details** on a paycheck where values/classifications need review or correction. Preserve authoritative paid values, component labels and tax buckets. Verify FIT taxable wages, capped SS wages/tips, uncapped Medicare wages and Additional Medicare wages from source evidence. Missing bases cannot be inferred by dividing rounded tax or treating gross as universally taxable. Confirm zero only when the source actually establishes zero. Optional provider payment references are retained as evidence and never allocated from Cornerstone’s check sequence.
6. For a missing payment, add a manual period with its actual boundaries/pay date and employee paycheck rows. Enter the same amounts, classifications, explicit wage bases and labeled component detail, then reconcile its register totals. An employee may appear only once on a pay date; combine source detail before entry if necessary. Periods must have ordered dates, a past pay date in the selected year and a pay date before takeover.
7. Attach the provider’s paid register evidence (PDF, CSV, Excel, text, JSON or image; 1–10 nonempty files, at most 10 MB each). Retain returns/deposit evidence with the client’s existing documents. Confirm complete already-paid history, unchanged employer identity and filing ownership only after the underlying evidence is checked. Saved progress keeps everything except attached files; reattach them after a reload.
8. Select **Check everything**. Correct any named mismatch, identity, missing-base, annual FICA or duplicate/overlap problem and check again. A changed source run invalidates its fingerprint; return to selection and reload/reconcile that source. Resolve unusual source FICA differences explicitly rather than reducing/zeroing balances to bypass the check.
9. Select **Record history…**, review the summary (pay dates, paychecks, gross/net and each employee’s year-to-date), tick the confirmation and record. Conversion retains and verifies the files plus a reviewed reconciliation JSON snapshot, creates dated historical periods/paychecks and existing-worker links, and retires the source runs in one transaction. Original inputs/calculations remain read-only evidence. They are neither committed nor voided and disappear as duplicate native entries from canonical payroll history. The original runs show as **Paid by previous provider** and link to this history.
10. Review counts, dates, gross/net, retained downloadable evidence and the cutoff in the saved history. For Kasperbauer expect 20 periods / 60 paychecks. Reload to verify the saved state. Do not activate partial coverage.
11. Select **Turn on year-to-date…**, review each employee’s totals and the filing ownership, tick the confirmation and confirm. Activation rechecks authority, identity and retained-file hashes, locks the archive, creates immutable employee/year opening balances, and applies the normal historical YTD bridge. No synthetic clean-client bootstrap or go-live predecessor/successor review is created.
12. Confirm filing ownership. For a November 1 takeover, Q1–Q3 Form 941 / Guam withholding / SWICA are external-provider reference history; Q4 and annual W-2GU/W-3SS are Cornerstone responsibility with imported history included. Responsibility is recorded separately for each filing type. The cutoff is evidence, not a replacement for dated October detail.
13. Create a fresh genuinely unpaid run strictly after both the imported period-end and pay-date boundaries. Complete normal setup/document gates, calculate, review and approve. Check employee YTD against the provider’s carry-forward and verify normal annual FICA evidence. Print/issue only genuine live payroll after ordinary commitment. Historical source runs cannot be recalculated, approved or committed.
14. Reconcile Q4 and annual returns to provider October wages plus later Cornerstone wages exactly once. Reconcile October DRT/EFTPS payments and later deposits separately against the full quarter’s liability; history does not manufacture deposit/payment records. Q1–Q3 exports remain reference-only and cannot be represented as Cornerstone filing-ready submissions.

## Reversal and limits

Before the first live commitment, select **Undo this history…**, enter the reason and tick the confirmation. First roll back approval and remove any downstream uncommitted payroll through the normal workflow; otherwise its calculation/approval would retain stale opening balances. Reversal refuses changed filing ownership, new filing-submission evidence or historical adjustments. It restores previous filing responsibility decisions, removes the bridge/archive from active readers, and returns source runs to calculated status while preserving the snapshots, source files, balances and audit records. Their retained paid-source provenance blocks live approval, commitment and transmittals even after reversal. Correct and reconvert them as history before processing new live payroll.

After any live payroll commitment, onboarding reversal is blocked. This first release also blocks the existing general historical-adjustment route for this provider: that schema does not carry explicit wage-base deltas. A later amendment workflow must preserve those bases and renew annual/filing review; direct SQL or a fabricated QuickBooks adjustment is not a supported repair. Archive correction is therefore an explicit pre-live acceptance responsibility.

Other deliberate limits: one complete employer/year, no historical opening-summary replacement for dated checks, no employer/EIN successor transfer, no contractor onboarding, no connected AIRE/timecard conversion, no payment/deposit automation, and no automatic certification that prior returns/deposits were correct. Those cases require their own supported source/review path.

## Implementation

- New `PriorProviderHistoryOnboarding` owns the attributed existing-roster contract, source reconciliation payload, request idempotency, activation and reversal evidence, and before/after filing ownership snapshots.
- `HistoricalImportBatch`, `HistoricalPayPeriod`, `HistoricalWorker`, `HistoricalPaycheck`, retained source files and `HistoricalEmployeeYtdBalance` remain the canonical financial/history records. Provider allowlists include `prior_provider`; the QuickBooks adapter retains its existing contract.
- A YTD bridge references exactly one roster contract: clean-client bootstrap or existing-roster onboarding. Database constraints and composite foreign keys preserve tenant identity.
- `retired_history` is a nonfinancial source-retirement state with a historical batch reference. Ordinary period/item edits and lifecycle transitions fail closed. Canonical history shows the historical replacements once.
- Annual FICA reads the applied opening balances through the existing normal context. W-2 uses explicit verified prior-provider FIT wages; quarterly readers use verified SS/tip/Medicare bases instead of gross-derived substitutes. Existing QuickBooks behavior remains intact.
- Company/period locks serialize conversion, activation, reversal, filing-responsibility edits and live-run creation. Conversion checks run fingerprints under those locks. Retries with the same request key and payload return the retained operation; a different payload cannot reuse the key.
- The additive migration is reversible on an unused rollout and takes about 0.08 seconds on the empty local fixture database. Existing converted/activated evidence must be handled before schema rollback; dropping financial evidence to force a rollback is not supported.
