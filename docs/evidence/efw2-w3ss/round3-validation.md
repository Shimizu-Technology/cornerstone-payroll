## Deployment

This round adds no schema migration or new worker service; the original PR migration remains required. Deploy the API with the existing shared Solid Cache and Solid Queue enabled and its default-queue worker running (`config/deploy.yml` enables the Puma supervisor; `config/queue.yml` consumes default). The first list visits after deploy enqueue accessible 2026 W-2 clients whose checks are missing/stale. Known issues remain actionable during the fill. Staff can use Refresh to see completed checks without opening every client.

An atomic cache lease deduplicates company/year/revision for one hour, with release on completion or enqueue failure; expiry permits recovery after worker loss. Each client has a separate job. Superseded revisions are skipped, cache writes remain bound to the revision read before computation, and failures log company/year/error class only. Failed checks can be requested again on a later load. Large initial backfills compete on the existing default queue; this introduces no polling or new recurring task.

A production frontend build is expected because this round changes the list UI. The locked-EIN test fixture now supplies every typed employer field. `npm run typecheck` and the first step of `npm run gate` now use the referenced-project build check, so app/test sources cannot silently escape typechecking.
