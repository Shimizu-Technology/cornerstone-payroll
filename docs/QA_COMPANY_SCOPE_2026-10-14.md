# Employee forms preserve their selected client

F14 from the retained Payroll/AIRE comprehensive QA audit: an employee form opened in an expiring test workspace could silently save into the accountant’s home client. Explicit company headers now fail closed; employee form and request scope must agree. No-header callers retain the existing home/assigned-company resolution.

Employee create/update locks the company, reloads and locks the actor and applicable assignments, and rechecks current staff role, action capability, payroll access, workspace grant and expiry before persistence. This serializes the employee save against the locked user/assignment changes. It does not claim serialization of every organization lifecycle operation. Rejections keep the browser draft and clearly state that nothing was saved.

Acceptance uses synthetic identities and two private PostgreSQL databases, on local Rails test and a development frontend. Actual computer use covered desktop creation with access expiring after form entry:403, retained fields and zero home-company records. At390x844, restoring that same synthetic grant allowed a retained-draft retry into the intended workspace. A fresh runtime retest also covered update:expired grant rejected the edited city with the stored value unchanged; restoring the same grant saved the retained edit only in workspace2. Fixture clock updates use UTC timestamps; an initial local-time SQL expiry attempt was discarded and repeated correctly.

Automated evidence: the final full backend passed4531 examples. Frontend types, strict lint, all unit tests, production build and security audits passed. Browser gates passed129 public,45 release,10 setup-refresh and24 pay-item scenarios. The pay-item lane used independently supervised canonical local servers after the managed browser host lost transport; assertions were unchanged and the failed harness attempts were preserved locally.
