# Portal file safety and attachment retention (PR 1a)

Clients and staff use the same server validator. It identifies bytes without a filename/MIME hint, checks the declared type against that result, and checks Office containers. Each file is limited to 25 MiB; a request accepts at most 10 files and 50 MiB total. OOXML accepts at most 1,000 entries and 100 MiB of actual decompressed data, with 5 MiB metadata sections. CSV/TXT accepts UTF-8, BOM-marked UTF-16LE/BE and Windows-1252 (decoded for validation without changing stored bytes). Control characters and binary content are rejected; CSV uses liberal quote parsing for POS exports. Macro-enabled Office extensions, VBA/Excel macro content, encrypted files, embedded programs and mismatched containers are rejected. These checks do not establish that a file is malware-free.

Uploads share the app's process-local Rack::Attack counter, keyed after authentication by user ID: 60 upload requests per minute across both namespaces and all companies. Invalid upload attempts count. Like the existing API throttles, this needs a shared cache before scaling to multiple web processes.

`ClientDocumentScanner.adapter` supplies `initial_status`, `scan(document:, storage:)`, and `allowed?(document:, purpose:)`. The no-op adapter leaves both existing and new files `not_scanned` and permits that legacy state. The common gate always blocks `infected`, `error`, and `pending`, even when an adapter would permit them. An enforcing adapter can start uploads `pending`; the scan job records its result and resumes preview generation after `clean`. If queue submission fails after commit, the original and pending record survive and the failure is logged for scanner recovery. Download, preview generation/serving, message attachment creation/change and `ensure_usable_for!(:intake)` all call the same gate. Future portal intake must use that method after resolving the document within the authorized company; no portal-to-intake bridge is added here.

## Required PR 1b rollout gate

Do not describe this release as malware protected or open the MoSa portal handoff pilot on the strength of these checks. PR 1b must deploy a measured, monitored scanner, configure an enforcing adapter that permits only `clean` at all four gates, backfill existing files without marking unscanned bytes clean, and verify infected/unavailable/retry outcomes end to end. Scanner cost and hosting remain Leon's decision. No default production setting is switched in PR 1a.

Each LibreOffice/Python process has a 45-second wall timeout, 30-second CPU limit, 100 MiB per-file output limit, 128 descriptors and capped diagnostic output. Linux also has a 1 GiB data/heap limit (`rlimit_data`). `rlimit_as` was removed because LibreOffice reserves large virtual mappings at startup; limiting all address space can prevent it from starting. Local Linux execution was blocked by the ASUS WSL host resource error, so Linux startup remains unverified here. The process group is killed on timeout. Only PATH, HOME/TMPDIR (the conversion directory), and LANG are explicitly passed, with `unsetenv_others: true`; database, storage and other application credentials are excluded. Conversion failure stays `failed` and can be retried with a unique Office profile; an existing preview storage reference survives a failed regeneration so a later success can clean it. macOS uses `sandbox-exec` to deny IP networking while allowing local Unix IPC needed by LibreOffice; Linux uses `/usr/bin/bwrap --unshare-net` when installed and permitted by the host. Network isolation requires that deployment support; there is no silent sandbox-failure retry outside it. No deployment or host package change is part of this PR.

Deleting a file referenced by a portal message, readiness requirement/history or filing evidence now archives it. It retains bytes, original name/title, message FK, archive actor/time and a named conversation tombstone. Clients cannot download or preview archived files, and neither role can attach them again or use them for new intake. Staff retain download/preview access (including generated Office previews), subject to the scanner gate. Staff can Unarchive from the documents page; the transaction audits the prior archive actor/time before clearing the archive fields. Unreferenced active files retain hard-delete behavior. Model guards and an additive PostgreSQL before-delete guard prevent retained-file destruction; company destruction is rejected before its callbacks can erase references. There is no purge or automatic retention duration.

Downloads and previews in both namespaces send `Cache-Control: private, no-store`, `X-Content-Type-Options: nosniff`, and sanitized disposition filenames. Existing company/visibility authorization remains in place.

## Round 2 compatibility corrections

Office chart embeddings may contain recursively validated `.xlsx`, `.docx` and `.pptx` packages, up to three embedding levels, sharing the outer file's 1,000-entry and 100 MiB expansion budget. OLE objects, executables, unknown embedded binaries and embedded macros remain rejected. Both Default and Override content-type declarations are checked for VBA/macro/ActiveX types, including neutral binary filenames. ZIP accepts at most 4 KiB of trailing NUL/ASCII whitespace padding; appended programs remain rejected. CSV also accepts the browser MIME aliases `application/csv` and `text/x-csv`. HTML/tab-delimited exports named `.xls` remain rejected with a plain request to export XLSX, CSV or PDF.

Both document pages split a single selection into sequential requests bounded by 10 files and 50 MiB. Visible progress counts finished files. An atomic 422 batch is retried one file at a time so valid neighbours can finish; failed filenames/reasons remain visible and only those files remain selected. Requests with uncertain network outcomes are not automatically repeated. At the 25 MiB/file maximum, 30 photos need 15 batches and at most 30 validation retries: 45 requests. The 60/minute allowance leaves 15 for corrections, while ordinary small photos need just three requests. Server byte/count limits remain unchanged.
