# Payroll UI-1a: shared primitives and accessibility

Owner: `payroll-impl-ui1a`. Base: `6b0c2c390501727639b46be72bfdeb5be0b43113`; target: `staging-v2`. The lead owns integration and merge.

Cornerstone accountants, including Chels, need to review Guam payroll while keeping saved compensation, source hours, checks, and payment evidence distinct. This slice implements DESIGN-SPEC A/B from the October 24 review. It preserves the blue identity, fonts, shell, pill buttons, report inventory, and accounting behavior. Dashboard/cutoff wording and page reorganization remain in later slices.

| Before | After | Why |
| --- | --- | --- |
| Gradient ground; shadowed and blurred shared cards | Flat neutral ground; white cards with a 12px radius and border | Reduce competing decoration in repeated operational views |
| Status badge text below normal-text contrast | Success-800, warning-800 and danger-700 on their 50 tints | Each actual token pair is measured in a unit test |
| Buttons lift, glow, and transition every property | Color hover, 150ms named transitions, 0.97 press scale | Keep frequent controls stable |
| Dialogs appear/disappear immediately | Interruptible 180ms panel entry, 150ms backdrop entry, 120ms opacity exit | Preserve context without delaying work; reduced motion has no scale |
| Tiny tracked labels; 14px phone fields | Minimum 12px metadata and sentence-case labels; 16px phone fields | Improve legibility and avoid the small-input zoom trigger |
| Routine deductions/net/DRT totals use red/green/amber | Ink and tabular figures in totals and the working register | Reserve semantic color for exceptions |
| Independent phone/report overlays | Shared dialog focus containment, inert background, Escape/backdrop close and opener return | Keep keyboard work inside the visible modal |
| `GMT+10` zone label | `ChST`, preserving the same Guam instant | Use the local zone name without changing time math |

The small-text sweep necessarily reaches files outside the pay-run page. Neutral token and label cleanup in those files is styling only. `ChecksPanel`, `VoidCheckModal`, and `CorrectivePaycheckModal` internals are unchanged. Two adjacent adaptations preserve existing behavior under the shared exit transition: General Transmittals supplies its explicit opener reference, and the unified check print dialog stops its PDF renderer when closed. The read-only payroll-item dialog retains its record during its fade and clears immediately on a scope change.

## Verification

Agent-executed QA used only task-owned headless Chromium and synthetic accountant fixtures, at 1280×800 and 390×844. APIs and web servers used assigned ports 48661–48667, with explicit isolated test database URLs. A read-only archive of the base web source supplied matched before captures. No production/staging, real email/payment/filing/provider calls, or borrowed-server requests were used.

The eight-case ledger covers dashboard/list inspection and action inventory, committed/draft run fold and scroll, employee-result filtering and dialog continuity, phone navigation, the package editor, targeted axe checks, motion, and browser timezone independence. The package journey generates a synthetic PDF, reloads the page, and verifies the saved preparer option; all five fixed enclosure fields remain read-only. The drawer is checked through 50 forward/backward Tab steps, Escape, backdrop close, route selection, and focus return. Normal and reduced-motion recordings capture repeated dialog open/close.

Existing dismissal tests now wait for the specified exit instead of assuming immediate unmount. Assertions for cancelled writes, retained drafts, scope isolation, renderer cleanup, and focus return remain. The release lane uses the new sentence-case column labels and explicit search name; coverage was retained.

Exact gate counts, final head, reviewer status, and cleanup are recorded in the task's `RESULT.md`. The local evidence bundle is `output/payroll-aire-review-2026-10-24/impl/payroll-ui1a/`, including:

- `EVIDENCE.html`, `before/`, `after/`, and `scroll-sheets/`;
- `action-inventory-diff.json`, `badge-contrast.json`, `compiled-hover.json`;
- `ui-verification.json`, `qa-ledger.json`, `axe-summary.json`, and raw axe reports;
- `recordings/dialog-no-preference.webm` and `recordings/dialog-reduce.webm`;
- full API/web/browser gate logs and Impeccable output/classification.

Impeccable 4.6.0 ran with telemetry disabled: five warnings, classified as four intentional choices and one false positive. The consequential correction/replacement warning accents and contracted font identity are intentional; the OCR flat indigo callout does not match the detector's gradient/neon claim.

The requested axe rule families are acceptance gates, rather than a claim of full WCAG conformance. Other pre-existing findings remain visible in the raw results: empty action-column headers, shortcut label/name mismatch, a nested interactive worksheet header, some scrollable-region focusability, and phone content outside landmarks (`region`). Native Safari, physical-phone keyboard/gestures, screen readers, printers, live transport/payment/filing, and operator acceptance were not tested.
