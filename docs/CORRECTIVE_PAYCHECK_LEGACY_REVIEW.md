# Existing corrective paycheck review

The cumulative correction flow requires verified version 1 input-adjustment history for every active prior corrective item. Older corrective entries without that history remain reportable, and their original payroll and payment evidence remain available. Further automated preview/issue is held with `MissingHistoricalContextError`; financial amounts alone cannot reconstruct the intended input change.

Before release, the deployment owner should run [the read-only inventory](../api/db/queries/legacy_corrective_context_inventory.sql) against an explicitly authorized reporting replica or selected database. It returns one row per affected original, grouped by company, original run/item and employee, with the active corrective IDs. Count returned rows for affected originals and sum `affected_active_corrective_count` for affected corrections. Keep results in the approved private payroll review location. This release includes no executed production inventory or automatic backfill.

For each affected original, payroll support should review the original committed inputs/calculation snapshots, all active and voided supplemental items, correction reasons, signed financial/YTD ledger and the original payment evidence. Record the desired absolute target and explain which historical inputs cannot be verified. Keep further automated correction held until an accountant approves a specific remediation with independently verified historical input evidence and a separate reviewed implementation or existing authorized manual accounting process. Do not infer or backfill input adjustments from gross/net alone or the employee's current rate, overwrite the original, void a linked source correction, or mark cash recovered without actual evidence.

For an exact source accounting correction, native void/cancel/replacement remains held until a supported atomic accounting reversal and source receipt contract exists. Read-only history now shows current proof failures as needs review; a previously confirmed receipt is historical evidence, not permission to bypass that hold.
