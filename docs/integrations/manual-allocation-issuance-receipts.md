Manual source hours become issued in Payroll only after the source proves the saved payment command. The receipt must include the original allocation, exact work identity and hours, payroll owner, issued payment event, payment tuple, event time, advancing version, command ID and verified installation descriptor. The immutable command result binds the saved expected version to its result version and captured allocation snapshot. Versions must advance; compatible producers may use a step greater than one and opaque string payment-event IDs. Fresh responses and replays use the same validation. A rejected receipt leaves the allocation committed, preserves the original issue intent, and records the existing visible sync error. Cancellation recovery must verify that same issuance receipt before adopting its version.

The installation UUID and verified protocol, capabilities and policy are saved with each new issue intent. This local evidence is excluded from the existing source command body. Replay validates the captured contract, so refreshing current capabilities or policy does not invalidate a previously issued receipt. The transport still checks the pinned installation and recognized protocol. Verify the source connection and install the Source receipt update before rolling out Payroll. No new endpoint, capability or database migration is required.

Older Source commands with minimal replay metadata cannot prove an immutable issuance receipt. Existing Payroll issue intents without a captured installation UUID and verified contract also remain blocked. Updating Source does not retroactively establish that missing evidence.

For an older pending intent, preserve its original command, arguments and allocation. Export that record together with the original local payment evidence and authenticated Source command, allocation and payment-event evidence. Verify the original installation UUID against evidence captured before the upgrade, such as the verified connection record and request audit. If both the original installation and the original command's complete immutable issued receipt are proven, a separately authorized recovery may add only the missing local installation and original verified contract evidence and retry the unchanged command. This change provides no recovery writer.

If the old command has only minimal replay metadata, keep the intent blocked and arrange separately authorized audited reconciliation with the Source owner. Do not clear the intent, create a replacement issue command, record another payment, or treat a current allocation snapshot as proof of the old command. Production reconciliation and real payments are outside this implementation's scope.
