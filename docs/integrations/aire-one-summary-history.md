# One-summary AIRE history approval

This held feature follows the segment-matching changes in Payroll #422 and AIRE #156. It is for a later activation setup, after the November 4 paused release. Approval records accounting coverage; it does not activate connected payroll, publish calendars, approve time, create payment allocations, send payment acknowledgements or assert check delivery.

An operator first prepares the unpublished maintenance phase: pinned installation, chosen first connected boundary, committed adjacent manual predecessor, authenticated paid-history baseline and personal AIRE account link. The existing connected-payroll pause still refuses integration reads and writes. This page does not change that flag. No calendar may have been prepared or published for the source.

An organization administrator or an accountant assigned to the client with payroll operations access opens **Client settings → Review AIRE history**. Managers and client users cannot approve. The server fetches the authenticated directory and full history, verifies saved person mappings, and suggests unambiguous exact matches. A nonexact selection must be explicitly confirmed on the summary. Proposed mappings are not saved until approval.

The summary shows source-entry counts/hours by the existing strict accounting types, separately signed employee/run/category rounding differences, owed entries including 1804 when its current case proves that debt, and the pending list. Frozen pending overtime and reported-payment evidence holds retain their distinct types. A split entry's pending list shows only its held overtime remainder. NULL approvals remain NULL. Unsupported or conflicting evidence defaults to pending review and blocks coverage; the UI cannot turn it into a paid or approved source record.

Only uniquely matched authenticated source categories and retained committed earning labels can prefill historical component bindings. Solo is never inferred. Rounding acknowledgements are generated for Chels's single attestation only when each signed difference is within ±0.05h; the existing verifier still binds the exact source, immutable batch, employee mapping and committed run. There is no netting across people or categories. Any out-of-policy or unexplained difference blocks history approval.

Solo earning choices are optional for history approval. The selects contain only the mapped employee's real active positive-rate earning components; no choice is preselected. An explicit choice is recorded with the reviewer and exact rate snapshot. A changed or removed rate invalidates that saved choice. Solo/Solo Hours never receives an automatic earning match in finalized import preview; unresolved Solo remains an import decision. An operator can explicitly choose an earning component during the existing import review as well.

History capture and approval run as durable background operations, so the browser does not hold a request open while thousands of source rows are verified. The page reads only local progress, pauses those reads while hidden, and stops them when the client or page changes. The worker rechecks access and the connected mode. A repeated identical approval request reuses the same operation. The terminal result commits in the same transaction as the approval; worker interruption cannot leave a committed approval with an uncommitted success result. A failed job retains its exact evidence-change explanation. Operators can retry an interrupted queued job through the existing job tooling; the transaction and approved-review guards make retries safe.

Chels ticks one attestation and clicks **Approve history**. The server recaptures authenticated evidence, checks the summary digest and current permissions, and lists changed entry IDs or local evidence sections if anything differs. The first full recapture runs before business-row locks. The atomic phase uses shared locks on only the referenced historical runs/items and selected employees, plus the source and reviewer guards. SQL lock acquisition is bounded at five seconds, SQL statements at twenty seconds, and the remaining approval phase at ten minutes. A busy or timed-out approval rolls back; it does not extend the deadline or weaken coverage. Current Payroll evidence is checked again after waiting for locks. Solo choices must belong to the Solo items actually shown on this summary. Within that transaction it saves confirmed mappings and optional Solo choices, builds exact acknowledgements against saved mapping identities, applies the accounting-only packet, invokes the same fresh completion gate used by `aire_rollout:ensure_complete`, and retains the actor, timestamp, original summary digest, approved packet digest and attestation. A failed completion rolls back mappings, choices, receipt and audit. No remote command is sent by this path, so rollback does not depend on undoing another app's writes.

Draft summaries expire after one hour and are tied to their client, source and actor. The browser cannot submit a packet or assert coverage. Approved reviews are immutable. Reloading shows the existing approval rather than requesting a second attestation. Approval still leaves publication, routing of owed cases, Solo decisions and switching to the intended connected operating mode as separate operator actions. The positive paired production-copy activation rehearsal remains an acceptance gate.
