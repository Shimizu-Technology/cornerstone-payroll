Payroll matches an unchanged owner report to an existing native issued payroll item. It creates a Source manual allocation receipt and retains the original report. It creates no paycheck or bank transfer. Native proof is the current delivered check or confirmed bank payment; commitment and printing are insufficient.

The optional `payment_attestation_resolution_v1` capability must be explicitly verified for every producer. The AIRE legacy capability list does not grant it. For an explicitly verified resolution producer, authorized attestation GET requests include both `start_date` and `end_date`; Source filters immutable original work dates before pagination. Legacy producer reads retain their previous query. The authoritative Source review supplies complete separate REG/OT hours and a weekly fingerprint. Payroll checks employee/company mapping, native proof and separate remaining item capacity. Cross-period adjustment items are supported.

Before POST, Payroll persists a normal manual-allocation capacity reservation containing the immutable resolution command, attestation version, complete Source identity/hours/fingerprint, actual payroll period/item, native payment tuple/time/event, Source installation contract and original operator binding. The advisory item lock spans reservation, remote command and local acknowledgement; short period/item row locks serialize local mutations. A lost response or invalid receipt keeps that reservation and command. Another operator, changed installation, changed delegation or replacement arguments cannot silently replace it.

A valid receipt proves both independently advancing report/allocation versions, identical immutable top-level and command-result snapshots, captured installation/contract, original report time and identity, exact hours/owner/payment/event/fingerprint and Source allocation/issued-event anchors. Current capability changes do not rewrite the captured contract. Acknowledgement sets the existing local allocation issued. Cancellation and replacement use the ordinary manual-allocation bridge; the resolved report and its original receipt remain historical evidence.

Uncertain resolution blocks payment method changes, item input changes, void, renumber/replacement events and whole-period retirement/revision. The operator sees a saved pending match and retries that exact command. Saved history remains visible during Source outages and after the pending Source list becomes empty. Matching a report does not add a second paid-hours total.
